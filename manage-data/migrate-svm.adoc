= 将存储虚拟机从ASA集群迁移到ASA r2 集群
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
从 ONTAP 9.18.1 开始，您可以无中断地将存储虚拟机 (VM) 从任何标准 ASA 集群迁移到任何 ASA r2 集群，以采用 ASA r2 系统面向纯 SAN 环境的简化、精简架构。


NOTE: 您无法将存储虚拟机从 ASA MetroCluster 迁移到 ASA r2 集群。ASA r2 系统不支持 MetroCluster 配置。

ASA r2 系统支持 QuickAssist 技术（QAT）。ASA 系统不支持 QAT。从 ONTAP 9.20.1 开始，ONTAP 降低了在将存储 VM 从 ASA（非 QAT）系统迁移到 ASA r2（QAT）系统后可能出现的高读取延迟和 CPU 使用率。

ASA和ASA r2 存储系统之间支持存储虚拟机迁移，具体方式如下：

[cols="2"]
|===
| 从以下任何ASA系统： | 适用于以下任何ASA r2 系统：

* ASA C800
* ASA C400
* ASA C250
* ASA A900
* ASA A800
* ASA A400
* ASA A250
* ASA A150
* ASA AFF A800
* ASA AFF A700
* ASA AFF A400
* ASA AFF A250
* ASA AFF A220

 a| 
* ASA A1K
* ASA C30

|===
有关ASA和ASA r2 系统的最新列表，请参阅link:https://hwu.netapp.com/["NetApp Hardware Universe"^]。  ASA r2 系统在NetAppHardware Universe中被列为“ASA A 系列/C 系列（新）”。

只能从 ASA 集群将存储虚拟机迁移到 ASA r2 集群。不支持从任何其他类型的 ONTAP 系统迁移到 ASA r2 系统。

.开始之前
ASA r2 集群和ASA集群中的所有节点必须运行ONTAP 9.18.1 或更高版本。集群节点上的ONTAP 9.18.1 补丁版本可能有所不同。



[[step-1-verify-the-status-of-the-asa-storage-vm]]
== 步骤 1：验证ASA存储虚拟机的状态

在将存储 VM 从ASA系统迁移之前，不应存在 NVMe 命名空间或vVols ，并且存储 VM 中的每个卷应仅包含一个 LUN。不支持迁移 NVMe 命名空间和vVols。  ASA r2 系统的架构要求卷包含单个 LUN。

.步骤
. 确认存储虚拟机中不存在 NVMe 命名空间：
+
[source, cli]
----
vserver nvme namespace show -vserver <storage_VM>
----
+
如果显示条目，则 NVMe 对象必须是link:https://docs.netapp.com/us-en/ontap/nvme/convert-namespace-to-lun-task.html["转换"^]添加到 LUN 或移除。参见 `vserver nvme namespace delete`以及 `vserver nvme subsystem delete`命令link:https://docs.netapp.com/us-en/ontap/concepts/manual-pages.html["ONTAP命令参考"^]了解更多信息。

. 确认存储虚拟机中不存在vVols：
+
[source, cli]
----
lun show -vserver <storage_VM> -class protocol-endpoint,vvol
----
+
如果存在任何vVols ，则应将其复制到另一个存储 VM，然后从要迁移的存储 VM 中删除。参见 `lun copy`和 `lun delete`命令link:https://docs.netapp.com/us-en/ontap/concepts/manual-pages.html["ONTAP命令参考"^]了解更多信息。

. 确认存储虚拟机中的每个卷都包含一个 LUN：
+
[source, cli]
----
lun show -vserver <storage_VM>
----
+
如果一个卷包含多个 LUN，请使用 `volume create`和 `lun move`创建 1:1 卷与 LUN 比例的命令。查看link:https://docs.netapp.com/us-en/ontap/concepts/manual-pages.html["ONTAP命令参考"^]了解更多信息。



.下一步是什么？
您已准备好在ASA和ASA r2 集群之间创建集群对等关系。



[[step-2-create-a-cluster-peer-relationship-between-your-asa-and-asa-r2-clusters]]
== 步骤 2：在您的ASA和ASA r2 集群之间创建集群对等关系

在将存储虚拟机从ASA集群迁移到ASA r2 集群之前，需要创建对等关系。对等关系定义了网络连接，使ONTAP集群和存储虚拟机能够安全地交换数据。

.关于此任务
ASA 集群是将从中迁移存储虚拟机的_源_集群，而 ASA r2 集群是将向其迁移存储虚拟机的_目标_集群。

.开始之前
您必须使用以下方法之一在被对等连接的集群中的每个节点上创建集群间 LIF。

* link:https://docs.netapp.com/us-en/ontap/peering/configure-intercluster-lifs-share-data-ports-task.html["在共享数据端口上配置集群间 LIF"^]
* link:https://docs.netapp.com/us-en/ontap/peering/configure-intercluster-lifs-use-dedicated-ports-task.html["在专用数据端口上配置集群间 LIF"^]
* link:https://docs.netapp.com/us-en/ontap/peering/configure-intercluster-lifs-use-ports-own-networks-task.html["在自定义 IP 空间中配置集群间 LIF"^]


.步骤
. 在目标集群上，与源集群创建对等关系并生成密码：
+
[source, cli]
----
cluster peer create -peer-addrs <source_cluster_LIF_IPs> -generate-passphrase
----
+
以下示例在集群 1 和集群 2 之间创建集群对等关系，并创建系统生成的密码短语：

+
[listing]
----
cluster1::> cluster peer create -peer-addrs 10.98.191.193 -generate-passphrase
Passphrase: UCa+6lRVICXeL/gq1WrK7ShR
            Peer Cluster Name: cluster2
            Initial Allowed Vserver Peers: -
            Expiration Time: 6/7/2017 09:16:10 +5:30
            Intercluster LIF IP: 10.140.106.185
Warning: make a note of the passphrase - it cannot be displayed again.

----
. 复制生成的密码短语。
. 在源集群上，创建与目标集群的对等关系：
+
[source, cli]
----
cluster peer create -peer-addrs <destination_cluster_LIF_IPs>
----
. 输入在目标集群上生成的密码短语。
. 验证集群对等关系是否已创建：
+
[source, cli]
----
cluster peer show
----
+
以下示例显示了成功建立对等连接集群的预期输出。

+
[listing]
----
cluster1::> cluster peer show

Peer Cluster Name   Cluster Serial Number   Availability   Authentication
-----------------   ---------------------   -------------- --------------
cluster2             1-80-123456             Available      ok
----


.结果
ASA和ASA r2 集群已建立对等连接，存储 VM 数据可以安全传输。

.下一步是什么？
您已准备好执行迁移预检查。



[[step-3-execute-the-migration-pre-check]]
== 步骤 3：执行迁移预检查

在将存储虚拟机从 ASA 集群迁移到 ASA r2 集群之前，您必须运行迁移预检查并修复任何需要解决的问题。在预检查成功通过之前，您无法执行迁移。

.关于此任务
ASA 集群是将从中迁移存储虚拟机的_源_集群，而 ASA r2 集群是将向其迁移存储虚拟机的_目标_集群。

.步骤
. 在目标集群中，执行迁移预检查：
+
[source, cli]
----
vserver migrate start -vserver <storage_VM> -source-cluster <sourcecluster> -check-only true
----
+
如果需要解决任何问题以准备迁移，则会显示问题和纠正措施。解决此问题并重复预检查，直到成功完成。



.下一步是什么？
您已准备好将存储虚拟机从ASA集群迁移到ASA r2 集群。



[[step-4-migrate-an-asa-storage-vm-to-an-asa-r2-cluster]]
== 步骤 4：将ASA存储虚拟机迁移到ASA R2 集群

在您准备好ASA集群并与ASA r2 集群建立必要的集群对等关系后，即可开始存储 VM 迁移。

执行存储 VM 迁移时，最佳实践是在ASA集群和ASA r2 集群上都留出 30% 的 CPU 余量，以便 CPU 工作负载能够执行。

.关于此任务
* 存储虚拟机迁移后，客户端 I/O 无缝过渡到目标集群，不会中断，并且 ASA r2 集群上的存储虚拟机会自动删除。默认情况下，自动切换和自动存储虚拟机删除处于启用状态。您可以选择禁用一个或两个选项并手动执行。
* ASA 集群是将从中迁移存储虚拟机的_源_集群，而 ASA r2 集群是将向其迁移存储虚拟机的_目标_集群。


.开始之前
* ASA r2 集群必须有足够的可用空间来容纳迁移的存储虚拟机。
* 如果ASA存储 VM 包含加密卷，则必须在集群级别配置ASA r2 系统上的板载密钥管理器或外部密钥管理器。
* 以下操作不能在源ASA集群上运行：
+
** 故障转移操作
** 华夫饼
** 指纹
** 卷迁移、重新托管、克隆、创建、转换或分析




.步骤
. 从目标集群开始 storage VM 迁移：
+
[source, cli]
----
vserver migrate start -vserver <storage_VM_name> -source-cluster <source_cluster>
----
+
要禁用自动切换，请使用  `-auto-cutover false` 参数。要禁用源存储虚拟机的自动删除，请使用  `-auto-source-cleanup false` 参数。

. 监控迁移状态
+
[source, cli]
----
vserver migrate show -vserver <storage_VM_name>
----
+
如果在自动切换开始前需要暂停或取消迁移，请使用以下方法： `vserver migrate pause`以及 `vserver migrate abort`命令。必须先暂停迁移，然后才能取消迁移。切换开始后，您将无法取消迁移。

+
如果启用了自动切换，则迁移完成后，*状态*将显示为*迁移完成*。如果禁用了自动切换，*状态*将显示为*准备进行源清理*。



.结果
storage VM 从 ASA 集群迁移到 ASA r2 集群。storage VM 的名称和 UUID、数据 LIF 名称、IP 地址和对象名称（如卷名）保持不变。storage VM 中已迁移对象的 UUID 已更新。

.下一步是什么？
如果禁用了自动切换和自动删除存储 VM，请执行迁移后切换和清理，以手动将 ASA 客户端切换到目标集群，并从 ASA 集群中删除存储 VM。



[[step-5-post-migration-cutover-and-cleanup]]
== 第 5 步：迁移后切换和清理

在集群间存储虚拟机迁移过程中，客户端 I/O 会过渡到目标集群，并且源集群上的存储虚拟机会被自动删除。如果您选择在迁移期间禁用源存储虚拟机的自动切换和删除，则需要在迁移状态达到 *准备进行源清理* 后手动执行这些步骤。



[[manually-cut-over-clients-after-a-storage-vm-migration]]
=== 在 Storage VM 迁移后手动切换客户端

如果在存储虚拟机的群集间迁移期间禁用自动客户端切换，则在迁移关系准备好切换后，手动执行切换，以便目标存储虚拟机可以向客户端提供数据。

.关于此任务
从目标集群执行此任务。

.步骤
. 手动执行客户端切换：
+
[source, cli]
----
vserver migrate cutover -vserver <storage_VM_name>
----
. 确认切换操作已完成：
+
[source, cli]
----
vserver migrate show
----


.结果
数据正在从目标集群上的 Storage VM 提供给您的客户端。

.下一步是什么？
现在可以从源集群中删除存储 VM。



[[manually-remove-a-storage-vm-after-migration]]
=== 迁移后手动删除 storage VM

如果在集群间存储 VM 迁移期间禁用自动源清理，则在迁移完成后，从源集群中删除存储 VM 以释放存储空间。

.开始之前
您的客户端应提供来自目标集群的数据。

.步骤
. 在源集群中，验证源存储 VM 的状态是否为*准备进行源清理*：
+
[source, cli]
----
vserver migrate show
----
. 删除源 storage VM：
+
[source, cli]
----
vserver migrate source-cleanup -vserver <storage_VM_name>
----


.结果
已删除源集群上的 Storage VM。
