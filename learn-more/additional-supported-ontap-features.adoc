= ASA r2 系统支持的常见ONTAP功能
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
由于 ASA r2 系统运行的是精简版 ONTAP，因此您执行许多常见 ONTAP 任务和 System Manager 功能的方式与其他 ONTAP 系统相同。

有关常见特性和功能的更多信息，请参阅以下ONTAP文档。



[[autosupport]]
== AutoSupport

从 ONTAP 9.20.1 开始，如果 AutoSupport 配置为 SMTP 协议而不是 HTTPs 协议，如果 AutoSupport 已禁用但仍配置了客户和合作伙伴电子邮件收件人，以及如果 AutoSupport 传输因 DNS 问题而失败，System Manager 将显示 AutoSupport 警报。

link:https://docs.netapp.com/us-en/ontap/system-admin/manage-autosupport-concept.html["详细了解 AutoSupport"^]。



[[data-protection]]
== 数据保护

[[clustered-external-key-servers]]
=== 集群外部密钥服务器

您可以配置与存储虚拟机上的群集外部密钥管理服务器的连接。使用群集密钥服务器，您可以在存储虚拟机上指定主密钥服务器和辅助密钥服务器。在注册密钥时，ONTAP 首先尝试主密钥服务器，然后顺序尝试辅助服务器，直到操作成功，从而防止重复密钥。

link:https://docs.netapp.com/us-en/ontap/encryption-at-rest/configure-cluster-key-server-task.html["学习如何配置集群式外部密钥服务器"^]。



[[external-key-management-for-encryption-at-rest]]
=== 静态加密的外部密钥管理

您可以使用一个或多个 KMIP 服务器来保护集群用于访问加密数据的密钥。

从 ONTAP 9.20.1 开始，当您在数据存储虚拟机上启用外部密钥管理器时，ONTAP 会自动将该存储虚拟机的卷加密密钥从管理范围密钥管理器迁移到新的数据存储虚拟机密钥管理器。这简化了向外部密钥管理的过渡，并消除了在标准工作流中执行单独手动迁移步骤的需要。

* link:https://docs.netapp.com/us-en/ontap/encryption-at-rest/enable-external-key-management-96-later-hw-task.html["启用外部密钥管理"^]。
* link:https://docs.netapp.com/us-en/ontap/encryption-at-rest/enable-external-key-management-96-later-nve-task.html["启用外部密钥管理 (NVE)"^] 。

[[administrator-access-management]]
=== 管理员访问管理

分配给管理员的角色决定了管理员可以执行的功能。System Manager 为集群管理员和存储 VM 管理员提供预定义角色。您可以在创建管理员帐户时分配角色，也可以稍后分配其他角色。

link:https://docs.netapp.com/us-en/ontap/task_security_administrator_access.html["学习如何使用系统管理器管理管理员访问权限"^]。



[[client-authentication-and-authorization]]
=== 客户端身份验证和授权

ONTAP使用标准方法来保护客户端和管理员对存储的访问，并防止病毒感染。先进技术可用于静态数据加密和 WORM 存储。  ONTAP通过与可信来源验证客户端计算机和用户的身份来验证其身份。  ONTAP通过将用户的凭据与文件或目录上配置的权限进行比较，来授权用户访问文件或目录。

link:https://docs.netapp.com/us-en/ontap/concepts/client-access-storage-concept.html["了解客户端身份验证和授权"^] 。



[[fc-sp-3-authentication-and-encryption]]
=== FC-SP-3 身份验证和加密

从 ONTAP 9.20.1 开始，ONTAP 支持在采用 ASA r2 系统的 Broadcom 安全 HBA 上进行光纤通道安全协议 3（FC-SP-3）身份验证和加密。FC-SP-3 支持实现硬件级端到端加密和设备身份验证，以保护在 FC 和 NVMe/FC SAN 主机与 ONTAP 存储系统之间传输的数据，同时符合 T11 光纤通道安全标准。

* link:https://docs.netapp.com/us-en/ontap/san-admin/fc-sp-3-security-support.html["了解 FC-SP-3 身份验证和加密"^]。




[[multi-admin-verification-mav]]
=== 多管理员验证（MAV）

从 ONTAP 9.20.1 开始，除了单个管理员之外，MAV 审批组还可以包括身份提供程序（IdP）、Active Directory（AD）和 LDAP（nsswitch）组作为审批者。支持的组类型包括 Entra ID、ADFS、AD 域组和 LDAP 组。在 IdP、AD 或 LDAP 目录中添加或删除用户不需要对 MAV 配置进行任何更改。link:https://docs.netapp.com/us-en/ontap/multi-admin-verify/index.html["详细了解 MAV"^]。



[[oauth-2-0-authentication]]
=== OAuth 2.0 身份验证

您可以使用开放授权（OAuth 2.0）框架来控制对ONTAP集群的访问。  OAuth 2.0 使用签名访问令牌来限制和控制对受保护资源的访问。

link:https://docs.netapp.com/us-en/ontap/authentication/overview-oauth2.html["了解 OAuth 2.0 身份验证"^] 。



[[saml-authentication-and-administrator-access]]
=== SAML身份验证和管理员访问

您可以为 Web 服务配置和启用安全断言标记语言 (SAML) 身份验证。  SAML 通过外部身份提供商 (IdP) 而不是目录服务提供商（例如 Active Directory 和 LDAP）来验证用户身份。

link:https://docs.netapp.com/us-en/ontap/system-admin/configure-saml-authentication-task.html["了解如何配置 SAML 身份验证"^]。



[[snmp]]
=== SNMP

从 ONTAP 9.20.1 开始，ONTAP 支持 SNMPv3 用户的 SHA-512 身份验证。此增强功能允许您将更强大的 SNMPv3 身份验证用于外部 SNMP 客户端和交换机监控，包括需要 SHA-512 身份验证的交换机。

* link:https://docs.netapp.com/us-en/ontap/networking/configure_snmpv3_users_in_a_cluster.html["了解如何配置 SNMPv3 用户"^]。
* link:https://docs.netapp.com/us-en/ontap-systems-switches/switch-cshm/config-snmpv3.html["了解如何在交换机上配置 SNMPv3"^]。




[[tls-hardware-offload]]
=== TLS 硬件卸载

您可以将整个集群的传输层安全性 (TLS) 加密和解密卸载到支持的以太网卡。这减少了 CPU 开销，并提高了使用 TLS 的系统的性能。

link:https://docs.netapp.com/us-en/ontap/networking/configure-tls-offload.html["了解如何配置 TLS 硬件卸载"^].



[[networking]]
== 网络连接

了解更多关于ASA r2 系统支持的常见网络功能。



[[fips-compliance]]
=== FIPS 合规性

ONTAP 符合所有 SSL 连接的联邦信息处理标准 (FIPS) 140-2。您可以打开和关闭 SSL FIPS 模式，全局设置 SSL 协议，并关闭 ONTAP 中的任何弱密码（例如 RC4）。

从ONTAP 9.18.1 开始，SSL 支持后量子计算加密算法。这些算法可针对未来潜在的量子计算攻击提供额外保护，并且在 SSL FIPS 模式禁用时可用。

* link:https://docs.netapp.com/us-en/ontap/networking/configure_network_security_using_federal_information_processing_standards_fips.html["学习如何为所有 SSL 连接配置 FIPS"^]。




[[link-aggregation-groups-lags]]
=== 链接聚合组（LAG）

接口组，也称为链路聚合组 (LAG)，是将同一节点上的两个或多个物理端口合并为一个逻辑端口而创建的。逻辑端口可提高弹性、可用性和负载分担能力。

link:https://docs.netapp.com/us-en/ontap/networking/combine_physical_ports_to_create_interface_groups.html["了解链接聚合组"^]。



[[performance]]
== 性能

详细了解 ASA r2 系统支持的常见性能功能。



[[modify-default-settings-that-control-automatic-qos-throughput-ceiling-increases]]
=== 修改控制自动 QoS 吞吐量上限增加的默认设置

默认情况下，自适应和非自适应 QoS 策略组暂时将工作负载的吞吐量上限提高 50%，持续 1 秒钟，以响应对更高性能的短期需求。从 ONTAP 9.19.1 开始，您可以修改这些设置。在 ONTAP 9.18.1 及更早版本中，您无法更改这些设置。

link:https://docs.netapp.com/us-en/ontap/performance-admin/guarantee-throughput-qos-task.html["详细了解 QoS 吞吐量上限"^].



[[ipspace-tcp-performance]]
=== IPspace TCP性能

从 ONTAP 9.19.1 开始，ONTAP 通过将两个丢包恢复功能 PRR 和 RACK 集成到 ONTAP TCP 堆栈中，提高了有损耗、高延迟 WAN 链路上的 TCP 数据传输性能。PRR 适用于所有网络，默认情况下处于启用状态。RACK 适用于链路速度约为 25 千兆位/秒的拥塞网络，默认情况下处于禁用状态。

link:https://docs.netapp.com/us-en/ontap/networking/improve-tcp-wan-performance.html["详细了解如何使用 PRR 和 RACK 提高 TCP WAN 性能"^]。



[[san-configuration]]
== SAN 配置

存储区域网络 (SAN) 由通过 iSCSI 或 FC 等 SAN 传输协议连接到主机的存储解决方案组成。您可以配置 SAN，以便存储解决方案通过一个或多个交换机连接到主机。如果使用 iSCSI，还可以配置 SAN，以便存储解决方案无需使用交换机即可直接连接到主机。



[[san-direct-attachment]]
=== SAN 直接连接

从 ONTAP 9.19.1 开始，无需 FC 交换机即可在 FC 和 FC-NVMe 主机与 ONTAP 存储之间建立连接。主机可以直接连接到 ASA r2 系统上的 FC 适配器端口。在简单性至关重要的远程站点和混合环境中，直接连接功能尤其有价值。

* link:https://docs.netapp.com/us-en/ontap/san-config/configure-fc-nvme-hosts-ha-pairs-reference.html#direct-attach-fc-and-fc-nvme-configurations["详细了解 SAN 直接连接"^].




[[san-protocols]]
== SAN协议

ASA r2 系统支持所有 SAN 协议（iSCSI、FC、NVMe/FC、NVMe/TCP）。

* link:https://docs.netapp.com/us-en/ontap/san-admin/san-host-provisioning-concept.html["了解更多关于 iSCSI 协议的信息"^]。
* link:https://docs.netapp.com/us-en/ontap/san-admin/san-provisioning-fc-concept.html["了解更多关于光纤通道 (FC) 协议的信息"^]。
* link:https://docs.netapp.com/us-en/ontap/concept_nvme_provision_overview.html["了解 NVMe 协议"^]。
+
** link:https://docs.netapp.com/us-en/ontap/san-admin/nvme-copy-offload.html["学习如何配置 NVMe 复制卸载"^]。
+
从 ONTAP 9.18.1 开始，ONTAP 支持 NVMe 复制卸载。NVMe 复制卸载使 NVMe 主机能够将复制操作从其 CPU 卸载到 ONTAP 存储控制器的 CPU。主机可以将数据从一个 NVMe 命名空间复制到另一个命名空间，同时为应用程序工作负载保留其 CPU 资源。

** link:https://docs.netapp.com/us-en/ontap/san-admin/enable-space-allocation.html["了解更多关于 NVMe 空间分配（取消映射）的信息"^]。
+
从ONTAP 9.16.1 开始，默认情况下为 NVMe 命名空间启用空间释放（也称为“打孔”和“取消映射”）。空间释放允许主机从命名空间中释放未使用的块以回收空间。







[[storage-efficiency]]
== 存储效率

存储效率是通过优化存储资源、最大限度地减少浪费的空间和减少写入数据的物理占用量来衡量存储系统有效利用可用空间的程度。

ONTAP 提供各种存储效率技术，可帮助您优化存储使用并降低成本。

link:https://docs.netapp.com/us-en/ontap/concepts/storage-efficiency-overview.html["详细了解 ONTAP 存储效率技术"].



[[data-reduction-rate-drr]]
=== 数据缩减率（DRR）

从 ONTAP 9.20.1 开始，存储效率数据缩减率（DRR）通过仅包含可缩减数据，提供了对 ONTAP 存储效率空间节省的更精确评估。在 ONTAP 9.19.1 及更早版本中，DRR 包括可缩减和不可缩减数据。

link:https://docs.netapp.com/us-en/ontap/concepts/capacity-measurements.html["详细了解 ONTAP 如何报告已用存储"^]。



[[global-deduplication]]
=== 全局重复数据删除

从 ONTAP 9.19.1 开始，_全局重复数据删除_将存储单元级别的 link:https://docs.netapp.com/us-en/ontap/concepts/deduplication-concept.html["现有 ONTAP 重复数据删除空间节省"^] 扩展到整个存储可用区（SAZ）。通过消除 SAZ 中所有存储单元中的重复数据块，您可以显著提高存储效率并降低总拥有成本。全局重复数据删除不需要功能许可证，默认情况下处于启用状态，与现有存储效率技术无缝集成，以最小的性能影响透明运行，无需管理配置。



[[system-manager]]
== System Manager

您可以在 System Manager 中搜索各种操作、对象和信息主题。您还可以搜索表格数据中的特定条目。

link:https://docs.netapp.com/us-en/ontap/task_admin_search_filter_sort.html["学习如何在系统管理器中搜索、筛选和排序信息"^]。



[[user-password-expiration-alerts]]
=== 用户密码过期提醒

从 ONTAP 9.20.1 开始，如果与用户帐户关联的角色配置了密码过期警报，则用户在登录后会立即在 System Manager 中收到页面顶部横幅警报，该警报从密码过期前 14 天开始显示。每次用户登录时都会更新警报，以显示距离密码过期的剩余天数。您可以在添加或编辑管理员角色时配置过期警报。

link:https://docs.netapp.com/us-en/ontap/authentication/configure-password-expiry-alerts.html["了解如何在 System Manager 中配置密码过期警报"^]。
